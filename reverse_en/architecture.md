## 1. Packaging & Module Structure

The application is packaged as a Java EE EAR:

```
kitchensink-ear.ear
├── kitchensink-ear-ejb.jar      (EJB 3.2 module)
├── kitchensink-ear-web.war      (WAR 1 — context root /kitchensink-ear-web)
├── kitchensink-ear-web2.war     (WAR 2 — context root /kitchensink-ear-web2)
└── META-INF/
    ├── application.xml          (J2EE 1.3 DTD — declares all three modules)
    └── weblogic-application.xml (WebLogic EAR-level descriptor)
```

**Maven build:** 4-module parent POM (`ejb` → `web` → `web2` → `ear`), Java source/target 8, Maven compiler plugin 3.8.0, EJB plugin 3.0, WAR plugin 2.5. Platform BOM: `wildfly-javaee7-with-tools:11.0.0.CR1` and `jboss-javaee-7.0:1.1.0.Final`.

## 2. EJB Module (`kitchensink-ear-ejb.jar`)

### 2.1 Domain Model

| Class | Type | Table | Notes |
|---|---|---|---|
| `Member` | `@Entity` + `@XmlRootElement` | `AA_Registrant` | `@UniqueConstraint(email)` |

**Fields:** `id` (`@Id @GeneratedValue Long`), `name` (String, max 25, no digits), `email` (String, unique), `phoneNumber` (String, 10–12 digits, column `phone_number`).

**Validation:** Mixes `javax.validation.constraints.*` (`@NotNull`, `@Size`, `@Pattern`, `@Digits`) with legacy **Hibernate Validator**-specific annotations (`org.hibernate.validator.constraints.Email`, `org.hibernate.validator.constraints.NotEmpty`).

### 2.2 Data Access

| Class | Scope | Role |
|---|---|---|
| `MemberRepository` | `@ApplicationScoped` CDI | JPA Criteria API queries: `findById`, `findByEmail`, `findAllOrderedByName` |
| `MemberListProducer` | `@RequestScoped` CDI | `@Produces @Named List<Member> getMembers()`; populates via `@PostConstruct`; refreshes on CDI `@Observes Member` events |

Both inject `EntityManager` via the CDI producer in `Resources`.

### 2.3 Service / Business Logic

| Class | Type | Transaction |
|---|---|---|
| `MemberRegistration` | `@Stateless` EJB | Container-Managed Transaction (CMT) — default `REQUIRED` |

`MemberRegistration.register(Member)` calls `em.persist(member)` then fires a `CDI Event<Member>` via `@Inject Event<Member> memberEventSrc`. The CDI event propagates the new member to all observers (i.e., `MemberListProducer`).

### 2.4 CDI Utilities

`Resources` (no scope annotation — dependent-scoped):
- `@Produces @PersistenceContext(unitName = "primary") EntityManager em` — bridges JPA container injection into CDI injection points.
- `@Produces Logger produceLog(InjectionPoint)` — SLF4J logger keyed to the declaring class.

**CDI activation:** `META-INF/beans.xml` with `bean-discovery-mode="all"`.

### 2.5 Integration Tests

`MemberRegistrationIT` — Arquillian/JUnit 4; deploys a ShrinkWrap WAR (Member + MemberRegistration + Resources); uses H2 in-memory datasource (`java:jboss/datasources/KitchensinkEarQuickstartTestDS`) configured in `test-ds.xml`; requires a running JBoss/WildFly container (JBOSS_HOME). `hibernate.hbm2ddl.auto=create-drop`.

## 3. Web Module (`kitchensink-ear-web.war`)

### 3.1 JSF Front-End

- **Facelets templating:** `WEB-INF/templates/default.xhtml` + `index.xhtml`.
- **View:** Member registration form (name, email, phone) and a data table of registered members.
- **EL bindings:** `#{newMember.*}` (from `MemberController@Produces`), `#{members}` (from `MemberListProducer@Produces`), `#{memberController.register}` action.
- **JSF version:** 2.2 (`faces-config.xml`); servlet activated by `faces-config.xml` presence (no explicit servlet mapping in `web.xml`).
- **`FacesContext` producer:** `WebResources` (`@RequestScoped`) produces `FacesContext.getCurrentInstance()` for CDI injection.

### 3.2 CDI Controller

`MemberController` (`@Model` = `@Named` + `@RequestScoped`):
- Injects `MemberRegistration`, `FacesContext`, `Logger`.
- Produces `@Named Member newMember` via `@PostConstruct initNewMember()`.
- `initNewMember()` also creates a test `Member` object and serialises it to JSON with **Google Gson** (diagnostic/test code left in production path).
- `register()` delegates to `MemberRegistration.register()`, adds `FacesMessage` on success/error.

### 3.3 JAX-RS REST API

**Activation:** `JaxRsActivator extends Application` annotated `@ApplicationPath("/rest")` — no `web.xml` servlet declaration needed.

**Endpoint:** `MemberResourceRESTService` (`@Path("/members")`, `@RequestScoped`):

| Method | Path | Produces | Consumes | Behaviour |
|---|---|---|---|---|
| `GET` | `/rest/members` | `application/json` | — | Returns all members ordered by name |
| `GET` | `/rest/members/{id}` | `application/json` | — | Returns member by id; 404 if not found |
| `POST` | `/rest/members` | `application/json` | `application/json` | Validates + registers member; returns 200/400/409 |

Validation in the REST layer: programmatic `Validator.validate()` (injected `javax.validation.Validator`), plus duplicate-email check via `MemberRepository.findByEmail`. Constraint violations return `400` with a field→message map; email conflict returns `409`.

### 3.4 Session & Charset Configuration

`web.xml` (Servlet 3.1): session timeout 30 minutes. `weblogic.xml`: input charset UTF-8 for all paths (`/*`), JSP `keepgenerated=true` + `debug=true`, context-root `/kitchensink-ear-web`. Container-descriptor entries (prefer-application-packages) are commented out — class-loading preferences are applied at EAR level instead.

## 4. Web2 Module (`kitchensink-ear-web2.war`)

A near-identical second web context rooted at `/kitchensink-ear-web2`. Differences from `web`:

| Aspect | `web` | `web2` |
|---|---|---|
| JSF controller | `MemberController` | `MemberControllerSecond` |
| REST service | `MemberResourceRESTService` | `MemberResourceRESTServiceSecond` |
| `@PostConstruct` init extra | Gson test serialisation | **Apache DeltaSpike** `ConfigResolver.getPropertyValue("config.key", "Default value")` |
| `weblogic.xml` extra | — | `<show-archived-real-path-enabled>true</show-archived-real-path-enabled>` |
| REST service logging | `logger.info(...)` in `listAllMembers` | No info log in `listAllMembers` |

Both WARs inject and call the **same** `MemberRegistration` EJB and `MemberRepository` CDI bean from the EJB module — they share a single persistence unit and database table.

`MemberResourceRESTServiceSecond` is functionally identical to `MemberResourceRESTService` with no behavioural differences.

## 5. Persistence Layer

| Property | Value |
|---|---|
| JPA version | 2.1 |
| Persistence unit name | `primary` |
| Datasource (JNDI) | `jdbc/SSA` (server-managed; not defined in the repo — must exist in the WebLogic/WildFly domain) |
| DDL strategy | `hibernate.hbm2ddl.auto=create-drop` (development setting — **destructive on restart**) |
| SQL logging | `hibernate.show_sql=true` |
| Entity | `Member` → table `AA_Registrant` |
| Transaction type | JTA (container-managed via `@Stateless` EJB) |

The `EntityManager` is obtained via `@PersistenceContext(unitName = "primary")` in `Resources` and re-exposed as a CDI producer for injection throughout the EJB module.

## 6. Transactions

All write operations use **Container-Managed Transactions (CMT)**. `MemberRegistration` is `@Stateless`; the container begins a JTA transaction before each method call and commits (or rolls back on exception) after. No `@TransactionAttribute` overrides are present — the default `REQUIRED` applies. No `@UserTransaction` / bean-managed transactions anywhere in the codebase.

## 7. CDI Event Bus

```
MemberRegistration.register()
  └─ memberEventSrc.fire(member)          [CDI Event<Member>]
       └─ MemberListProducer.onMemberListChanged(@Observes Member)
            └─ retrieveAllMembersOrderedByName()  → refreshes members list
```

`Reception.IF_EXISTS` means the observer is only notified when the `MemberListProducer` bean already exists in the context (i.e., the current request scope has already injected it). This drives the data-table refresh without polling.

## 10. Component Interaction Diagram

```
HTTP Browser
  │
  ├─ GET/POST /kitchensink-ear-web/*
  │    └─ WildFly/WebLogic: routes to kitchensink-ear-web.war
  │         ├─ JSF FacesServlet
  │         │    └─ MemberController (@Model)
  │         │         └─ MemberRegistration (@Stateless EJB) ─── JTA TX ──► EntityManager
  │         └─ JAX-RS RestEasy/Jersey
  │              └─ MemberResourceRESTService (@RequestScoped)
  │                   ├─ MemberRepository ─────────────────────────────► EntityManager
  │                   └─ MemberRegistration (@Stateless EJB) ─── JTA TX ──► EntityManager

  └─ GET/POST /kitchensink-ear-web2/*

            ├─ JSF FacesServlet

            │         └─ MemberRegistration (@Stateless EJB) ─── JTA TX ──► EntityManager
```

## 11. Runtime Container Assumptions (WebLogic / WildFly)

The following are **provided by the container** at runtime — the application carries no bundled implementation:

| Provided service | How consumed |
|---|---|
| JTA transaction manager | CMT via `@Stateless` EJB |
| JPA provider (Hibernate ORM) | `@PersistenceContext` / `persistence.xml` |

| Google Gson 2.8.6 | Provided scope in web POM; must be on server or in shared lib |

## 12. Security

**No security configuration is present.** There are no `<security-constraint>`, `<login-config>`, or `<security-role>` entries in any `web.xml`. No `@RolesAllowed`, `@PermitAll`, or `@DenyAll` EJB annotations are used. All endpoints (JSF and REST) are open with no authentication or authorisation.

## 13. Migration Complexity Summary

| Area | Signal | Severity |
|---|---|---|
| Namespace | All `javax.*` imports → must rename to `jakarta.*` | Blocker |
| WebLogic descriptors | `weblogic-application.xml`, `weblogic.xml` — no Spring Boot equivalent | Blocker |
| EAR packaging | No EAR in Spring Boot; decompose to single flat JAR | Blocker |
| `CommonLibsWarForEar` shared library | Must be inlined or replaced | Blocker |
| JNDI datasource `jdbc/SSA` | Replace with Spring Boot `spring.datasource.*` | Blocker |
| `hibernate.hbm2ddl.auto=create-drop` | Unsafe for production; replace with Flyway/Liquibase | Major |
| JSF (Facelets) | No first-class Spring Boot support; replace UI layer (Thymeleaf, REST+SPA, or Joinfaces) | Major |
| CDI (`@Inject`, `@Produces`, `@Model`, events) | Replace with Spring `@Component`/`@Service`/`@Bean`/`ApplicationEvent` | Major |
| `@Stateless` EJB / CMT | Replace with Spring `@Service` + `@Transactional` | Major |
| Apache DeltaSpike `ConfigResolver` | Replace with `@Value` / Spring `Environment` | Major |
| Hibernate Validator deprecated annotations | `@Email` → `jakarta.validation.constraints.Email`; `@NotEmpty` → `@NotBlank` | Major |
| Dual-WAR (`web` + `web2`) | Near-identical; consolidation opportunity — single Spring Boot app | Minor |
| Google Gson usage in `MemberController.initNewMember()` | Diagnostic/dead code; review and remove or replace with Jackson | Minor |
| Spring Framework 4.3.9 in root POM | Declared but unused — remove property; Spring Boot 3.4 brings its own Spring 6.x | Minor |
| Arquillian tests | Replace with `@SpringBootTest` / `MockMvc` | Minor |
| Session sharing (`sharing-enabled=true`) | Evaluate if cross-module session sharing is needed in flat Spring Boot JAR | Info |
