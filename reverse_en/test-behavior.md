## 2. Behavioural Characterisation (static, from source)

### 2.1 Domain Model — `Member` (table `AA_Registrant`)

| Field | Constraints | Column | Notes |
|---|---|---|---|
| `id` (Long) | `@Id @GeneratedValue` | PK auto | Generated by JPA strategy default |
| `name` (String) | `@NotNull @Size(min=1,max=25) @Pattern(regexp="[^0-9]*", message="Must not contain numbers")` | `name` | Rejects digits; 1–25 chars |
| `email` (String) | `@NotNull @NotEmpty @Email` (Hibernate Validator) | `email` | Table-level `UNIQUE` constraint |
| `phoneNumber` (String) | `@NotNull @Size(min=10,max=12) @Digits(fraction=0,integer=12)` | `phone_number` | 10–12 digit string |

- `@XmlRootElement` present (JAXB) — used for XML/JSON marshalling in JAX-RS
- `@NotEmpty` and `@Email` are **legacy Hibernate Validator** annotations (`org.hibernate.validator.constraints`) — not in `jakarta.validation.constraints`

### 2.2 MemberRepository (`@ApplicationScoped` CDI)

| Method | Query | Not-found behaviour |
|---|---|---|
| `findById(Long)` | `EntityManager.find(Member.class, id)` | Returns `null` |
| `findByEmail(String)` | JPA Criteria, `getSingleResult()` | Throws `NoResultException` |
| `findAllOrderedByName()` | JPA Criteria, order by `name` asc | Returns empty `List` |

**Known risk:** `findByEmail` uses `getSingleResult()` — if the DB ever holds two rows with the same email (e.g. constraint was dropped), it will throw `NonUniqueResultException` (unchecked), which propagates unhandled to the REST layer and surfaces as a 400 with a generic error body.

### 2.3 MemberRegistration (`@Stateless` EJB)

```
register(Member member):
  1. logger.info("Registering " + name)
  2. em.persist(member)             — JTA transaction (container-managed, @Stateless boundary)
  3. memberEventSrc.fire(member)    — CDI Event<Member>; triggers MemberListProducer.onMemberListChanged
```

- Transaction scope: full method. JPA `persist` and CDI event both run inside one JTA transaction.
- `member.id` is populated by JPA after `persist` (in-transaction; auto-generated).
- No `try/catch` — persistence exceptions (constraint violations) propagate to the caller; JTA container rolls back the transaction.

### 2.4 MemberListProducer (`@RequestScoped` CDI)

- `@PostConstruct retrieveAllMembersOrderedByName()` — populates `members` list on bean creation
- `@Observes(IF_EXISTS) Member` — refreshes the list when a `Member` CDI event fires (only if bean is in scope)
- `@Produces @Named` `getMembers()` — exposes `List<Member>` as EL variable `members` in JSF views

### 2.6 MemberResourceRESTService (`@Path("/members") @RequestScoped`, web module)

Context root: `/kitchensink-ear-web/rest`

| HTTP | Path | Logic | Response |
|---|---|---|---|
| GET | `/members` | `repository.findAllOrderedByName()` | 200 JSON array |
| GET | `/members/{id:[0-9][0-9]*}` | `repository.findById(id)`, null→404 | 200 JSON or 404 |
| POST | `/members` | validate → register → ok | 200 / 400 / 409 / 400(generic) |

**POST flow:**
```
validateMember(member):
  violations = validator.validate(member)
  if !violations.isEmpty → throw ConstraintViolationException  → 400 {field: message, ...}
  if emailAlreadyExists(email)  → throw ValidationException    → 409 {"email": "Email taken"}

emailAlreadyExists(email):
  try { repository.findByEmail(email) }
  catch(NoResultException) { /* ignore */ }
  return member != null

registration.register(member)  → 200 ok

catch(ConstraintViolationException) → 400 {field→message map}
catch(ValidationException)          → 409 {"email": "Email taken"}
catch(Exception)                    → 400 {"error": e.getMessage()}
```

**Subtle behaviour:** `emailAlreadyExists` catches only `NoResultException`; an unexpected `NonUniqueResultException` from `findByEmail` would fall through to the generic `catch(Exception)` block and return a 400 with the exception message — not a 409.

## 4. Migration Mapping Notes

| Old (JEE 7 / `javax.*`) | New (Spring Boot 3.4 / Jakarta) |
|---|---|
| `MemberRegistrationIT` (Arquillian) | `@DataJpaTest` for repo + `@SpringBootTest` for service |
| `javax.validation.*` | `jakarta.validation.*` |
| `javax.annotation.PostConstruct` | `jakarta.annotation.PostConstruct` |
| `javax.xml.bind.annotation.XmlRootElement` | Drop — Jackson handles JSON; no JAXB needed |
| `org.hibernate.validator.constraints.Email` | `jakarta.validation.constraints.Email` |
| `org.hibernate.validator.constraints.NotEmpty` | `jakarta.validation.constraints.NotBlank` |
| JUnit 4 `@RunWith(Arquillian.class)` | JUnit 5 `@ExtendWith(SpringExtension.class)` or `@SpringBootTest` |
| `Event<Member>` CDI event + `@Observes` | `ApplicationEventPublisher.publishEvent` + `@EventListener` |
| `@Stateless` EJB + JTA | `@Service` + `@Transactional` (Spring) |
| `@ApplicationScoped` CDI | `@Repository` + Spring-managed bean |
| JSF `FacesContext` / `FacesMessage` | Thymeleaf model attributes or redirect-with-flash |
| Gson in `MemberController` `@PostConstruct` | Remove (dead test code; do not migrate) |
